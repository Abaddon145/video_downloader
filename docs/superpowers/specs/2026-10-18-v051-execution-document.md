# 第一部分：P0 — Obsidian Vault not found 修复

## 1. 问题描述

用户实际使用映流 v0.5.0 时：

1. 打开映流知识库。
2. 选择已保存的 Markdown 笔记。
3. 点击「在 Obsidian 中打开」。
4. 系统成功启动 Obsidian。
5. Obsidian 弹出错误：

```text
Error

Vault not found.

Unable to find a vault for the URL
obsidian://open?path=...
```

该问题已在用户实际运行环境中出现。

### 当前相关文件

- `src-tauri/src/knowledge/obsidian.rs`
- `src-tauri/src/knowledge/service.rs`
- `src-tauri/src/knowledge/commands.rs`
- `src/features/knowledge/KnowledgePage.tsx`

当前 `obsidian.rs` 使用绝对文件路径生成：

```text
obsidian://open?path=<absolute-path>
```

这是一种官方支持的 URI 形式，但它要求 Obsidian 能找到包含该文件的已登记 Vault。

**普通 Markdown 文件夹不等于已经在 Obsidian 中登记的 Vault。**

不能假设 Windows 已启动 Obsidian 就表示目标笔记已经成功打开。

## 4. 修改 Obsidian URI 生成策略

目标文件：

`src-tauri/src/knowledge/obsidian.rs`

增加明确的两种 URI 构造方式。

### 方案 A：已登记的 Vault

优先使用：

```text
obsidian://open?vault=<vault-id>&file=<relative-note-path>
```

使用用户确认的 Obsidian Vault ID；只有在用户明确提供并确认名称时，才使用 Vault 名称。

相对路径必须从当前 Vault 根目录计算。

例如：

```text
Vault根目录：

C:\Users\User\Documents\映流知识库

笔记：

C:\Users\User\Documents\映流知识库\UE5\Niagara.md
```

对应：

```text
vault=<用户确认的Vault标识>

file=UE5/Niagara.md
```

所有参数通过成熟的 URL API 进行正确编码。

### 方案 B：绝对路径

保留：

```text
obsidian://open?path=<absolute-path>
```

作为兼容方式。

但必须明确：

它不能自动解决未登记 Vault 的问题。

### 特殊路径

必须兼容：

- 中文路径
- 空格
- `#`
- `&`
- `?`
- `%`
- Unicode
- Windows 正常盘符路径
- Windows 长路径前缀

不得出现重复 URL 编码。

不得把未经编码的文件名直接拼接进 URI。

不得把不存在、非 Vault 内部或路径校验失败的文件交给 Obsidian。

## 5. 修正打开成功的判断

当前问题之一：

`KnowledgeService::open_in_obsidian()` 调用系统外部打开机制后，即可能返回「已请求在 Obsidian 中打开」。

必须区分：

**系统接受外部 URI 启动请求**

与：

**Obsidian 确认打开指定笔记**

这两件事不是同一状态。

### 修复要求

- 系统 URI 调用失败时，显示具体原因。
- URI 调用成功时，只提示「已向 Obsidian 发送打开请求」。
- 如果没有可靠的应用级回执，不得提示「笔记打开成功」。
- 提供「无法打开？」故障排查入口。
- 允许用户重新选择 Vault。
- 无法联动时保留在映流中编辑的能力。

不必为了这项修复立即开发复杂的 Obsidian 插件或后台通信服务。

如果用户还没有在 Obsidian 中添加当前知识库，映流需要提供：

## 7. 多 Vault 处理

必须考虑：

- 用户拥有多个 Obsidian Vault。
- 用户同时有私人 Vault 和映流 Vault。
- 不同 Vault 存在同名笔记。
- 映流 Vault 目录被移动。
- Vault 被 Obsidian 从列表中移除。
- 用户更换 Windows 电脑。

要求：

- 映流不能随便用最后打开的 Obsidian Vault。
- 不能只使用笔记文件名寻找目标。
- 必须以映流知识库根目录和确认的 Vault 标识建立关联。
- 路径发生变化后要求重新验证。
- 绑定失败不影响 Markdown 文件读取。

- Vault 是普通磁盘文件夹。
- 兼容 YAML Frontmatter。

- 兼容附件和图片。
- 兼容标签。
- 允许外部 Obsidian 修改。

禁止：

- 私自安装 Obsidian 插件。
- 捆绑官方 Obsidian 客户端。
- 因联动失败自动迁移或复制全部笔记。
- 修改源 Markdown 以绕过 URI 问题。

## 9. Obsidian专项测试

至少增加：

- 已安装 Obsidian，Vault 已登记。

- 未安装 Obsidian。

- 用户使用多个 Vault。
- 知识库路径包含中文。

- Vault 根目录变动。

- 用户没有权限访问目标文件。
- Obsidian 已在后台运行。
- Obsidian 完全关闭后通过 URI 唤起。
- 映流笔记有尚未保存的修改。

对于无法自动验证实际打开成功的场景，保留明确的 Windows 人工验收步骤。

## 最终产品目标

**映流 Yingliu v0.5.1**

从视频下载与学习工具升级为：

**可高度自定义的本地视频学习与知识管理工作台。**

- 学习库是视频学习中心。
- AI服务于具体课程。
- 知识库拥有 DCC 风格的专业编辑体验。
- Markdown 数据始终归用户所有。
- Obsidian 联动可靠、可诊断、可配置。
- 工作区布局可以根据不同使用场景自由调整。
- 右键菜单让高频操作更高效。
- AI模板能够匹配不同类型的课程。
- 稳定性和数据保护优先于新增功能数量。

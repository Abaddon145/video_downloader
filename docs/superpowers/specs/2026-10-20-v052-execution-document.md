**项目名称：** 映流 Yingliu  
**目标版本：** v0.5.2  
**GitHub 仓库：** `Abaddon145/video_downloader`  
**参考基线：** v0.5.0、PR #8、PR #9，以及已有的 v0.5.1 工作区与知识库升级任务

# 一、项目目标

本次升级的重点不是简单地增加动画或美化按钮，而是将映流从普通的视频下载与学习工具，升级为具有专业桌面软件交互体验的本地视频学习工作台。

重点参考以下产品的交互理念：

- Obsidian：Markdown 实时预览、知识管理、双向链接。
- Raycast：全局命令面板、键盘优先操作。
- Linear：快捷操作、状态反馈、简洁交互。
- VS Code：命令搜索、快捷键、可定制工作区。
- 专业视频软件：可调整面板、播放器控制、工作区预设。
- 现代下载管理器：后台任务、进度反馈、失败恢复。

这些是交互设计参考，不要求照搬其他软件的外观，也不要求引入所有参考项目的依赖。

## 1.1 核心目标

1. 建立全局命令面板，减少重复点击。
2. 建立统一的上下文菜单和快捷键系统。
3. 优化知识库编辑体验，采用 Obsidian 式 Live Preview。
4. 让学习库和视频播放器根据窗口大小自动调整布局。
5. 增加工作区布局预设与面板自定义。
6. 建立统一的后台任务中心。
7. 为重要操作提供撤销、恢复和明确的结果反馈。
8. 增强视频、字幕、AI、知识笔记之间的联动。
9. 统一全软件的加载、空状态、错误和成功状态。
10. 提升键盘可操作性、窗口缩放适配和长期使用稳定性。

## 1.2 不允许破坏的现有功能

- 视频下载与本地文件管理。
- 学习库课程、系列和播放进度。
- 原生 mpv 播放器。
- Whisper 字幕。
- DeepSeek AI 分析。
- AI 总结、字幕、问答和笔记。
- Markdown 知识库。
- Obsidian Vault 联动。
- `yingliu://video/` 课程时间点链接。
- 已有学习记录、AI 分析历史和知识笔记。
- 已完成的右键菜单、工作区配置和知识库功能。

不得为了交互升级而重建整个应用框架。

# 三、P0：全局命令面板

这是本次最值得优先开发的功能。

## 3.1 功能目标

用户不必逐层打开导航、查找按钮，而是可以通过键盘直接搜索并执行命令。

默认快捷键：

`Ctrl+K`

同时提供：

- `Esc`：关闭。
- `↑ / ↓`：选择命令。
- `Enter`：执行。
- `Tab`：切换搜索结果区域或命令分类。
- `Ctrl+K`：已打开时按产品约定切换或关闭。

快捷键必须支持用户自定义，并避免与输入框、系统快捷键及现有编辑器快捷键冲突。

## 3.2 命令面板界面

包含：

- 搜索框。
- 最近使用。
- 命令分类。
- 搜索结果。
- 快捷键提示。
- 无结果状态。
- 执行中的状态。
- 错误反馈。

搜索结果需要支持键盘导航，当前选中项必须有清晰的高亮状态。

界面应轻量，不应遮挡整个应用，也不应因为打开命令面板而卸载正在播放的视频。

## 3.3 第一批内置命令

### 全局导航

- 打开下载。
- 打开学习库。
- 打开知识库。
- 打开媒体工具。
- 打开历史。
- 打开设置。

### 学习库

- 搜索课程。
- 播放当前课程。
- 从上次位置继续。
- 切换播放布局。
- 打开字幕。
- 打开 AI 学习面板。
- 分析当前视频。
- 生成课程笔记。

### 知识库

- 新建笔记。
- 搜索笔记。
- 打开最近笔记。
- 切换实时预览与源码模式。
- 插入视频时间点。
- 创建模板笔记。
- 打开版本历史。
- 在 Obsidian 中打开当前笔记。

### 工作区

- 切换工作区预设。
- 切换紧凑模式。
- 切换专注模式。
- 恢复默认布局。

### 文件管理

- 打开下载目录。
- 打开最近文件。
- 查看后台任务。
- 查看失败任务。

## 3.4 命令注册架构

建议建立统一的 `CommandRegistry`。

每个命令至少包含：

- `id`
- `title`
- `description`
- `category`
- `keywords`
- `shortcut`
- `enabled`
- `execute`
- `requiresConfirmation`
- `availabilityReason`

以上为建议字段，实际类型需要按项目架构实现。

要求：

1. 不在命令面板组件中硬编码所有业务逻辑。
2. 命令面板、工具栏、快捷键可以调用相同的命令。
3. 命令不可执行时，显示禁用原因。
4. 对删除、批量移动等危险操作仍需确认。
5. AI 分析命令必须检查任务状态，防止重复提交。
6. 当前课程不存在时，不能执行依赖当前课程的命令。

## 3.5 搜索体验

支持：

- 命令名称。
- 同义词。
- 模糊匹配。
- 中文与英文关键词。
- 最近使用。
- 常用命令排序。

例如输入“笔记”“note”“新建笔记”都能找到创建笔记命令。

最近使用记录只保存必要的命令标识和时间，不保存 API Key、敏感内容或完整笔记正文。

# 四、P0：统一快捷键系统

## 4.1 建立 ShortcutManager

全软件共享一套快捷键注册与冲突检测机制。

功能：

- 注册快捷键。
- 取消注册。
- 检查快捷键冲突。
- 支持用户自定义。
- 显示当前快捷键。
- 恢复默认。
- 按模块查看快捷键。
- 允许导入导出快捷键配置。

## 4.2 默认快捷键建议

| 快捷键 | 功能 |
|---|---|
| Ctrl+K | 全局命令面板 |
| Ctrl+P | 快速搜索课程与笔记 |
| Ctrl+Shift+N | 新建笔记 |
| Ctrl+S | 保存当前笔记 |
| Ctrl+Z | 撤销当前编辑操作 |
| Ctrl+Shift+Z | 重做 |
| Space | 在播放器获得焦点时播放/暂停 |
| J / L | 在播放器获得焦点时后退/前进 |
| Shift+F10 | 打开上下文菜单 |
| Esc | 关闭当前弹层或退出当前交互 |
| F11 | 全屏或按应用现有规则切换全屏 |

注意：

- 不允许播放器快捷键劫持正在输入的文本。
- 不允许覆盖操作系统或输入法的关键操作。
- 快捷键必须遵守焦点上下文。
- `Ctrl+Z` 必须作用于当前编辑器或当前支持撤销的业务操作，不能同时撤销多个无关操作。

## 4.3 快捷键帮助

增加快捷键帮助面板：

- 按模块分类。
- 支持搜索。
- 显示当前实际绑定。
- 显示冲突。
- 支持恢复默认配置。

# 六、P1：Obsidian 式实时编辑与知识库交互

本部分必须与已有的《映流 v0.5.2 Obsidian式实时编辑与自适应播放器 UI 优化 Codex执行文档》保持一致。

## 6.1 默认使用 Live Preview

默认模式应为实时预览，而不是满屏 Markdown 源码。

继续使用 CodeMirror 6，优先增加 Markdown Live Preview 扩展。

必须支持：

- 标题。
- 粗体与斜体。
- 列表。
- 引用。
- 代码块。
- 表格。
- 图片。
- 链接。
- YAML Frontmatter。
- Obsidian Wiki Links。
- 附件链接。
- 映流视频时间点链接。

不支持的语法必须保留原始内容，不得静默删除。

## 6.2 编辑器与操作栏

将高频操作放在正文附近：

- 标题。
- 格式化。
- 插入链接。
- 插入图片。
- 插入视频时间点。
- 保存状态。
- AI 整理。

低频操作进入“更多”菜单：

- 历史版本。
- 移动。
- 导出。
- 附件管理。
- 思维导图。
- 删除。

## 6.3 编辑器状态

明确区分：

- 未修改。
- 正在编辑。
- 保存中。
- 已保存。
- 保存失败。
- 外部修改冲突。

禁止通过定时器或虚假状态显示“已保存”。

## 6.4 选区上下文操作

当用户选中文字时，可显示轻量浮动工具栏：

- 加粗。
- 斜体。
- 插入链接。
- 添加引用。
- AI 总结。
- AI 润色。
- 创建复习问题。

浮动工具栏不能遮挡选区，不能打断中文输入法组合输入，也不能在选择链接时意外打开视频。

AI 修改必须先展示结果，用户确认后才能应用。

# 八、P1：自适应布局与工作区预设

## 8.1 响应式布局

必须使用真实容器尺寸决定布局。

推荐：

- CSS Container Queries。
- ResizeObserver。
- 已有的 WorkspaceProvider。
- 统一面板尺寸管理。

避免仅依赖 `window.innerWidth`。

## 8.2 布局模式

内置：

- 标准学习。
- 剧院模式。
- 专注播放。
- 上下布局。
- 知识整理。
- 批量管理。

用户可以：

- 折叠侧栏。
- 拖动分隔线。
- 隐藏非必要面板。
- 调整卡片大小。
- 保存当前布局。
- 切换布局预设。
- 恢复默认布局。

## 8.3 布局持久化

保存：

- 面板宽度。
- 面板高度。
- 面板折叠状态。
- 视图模式。
- 可见列。
- 卡片尺寸。
- 当前预设。

当窗口过小时，使用临时适配尺寸，不得直接覆盖用户保存的桌面布局。

恢复默认布局只影响界面设置，不得删除课程、笔记、AI 记录或播放进度。

# 九、P1：后台任务中心

## 9.1 统一任务视图

建立任务中心，集中展示：

- 视频下载。
- AI 分析。
- 字幕生成。
- 缩略图生成。
- 视频转换。
- 知识笔记生成。

优先接入已有任务系统，不重复创建任务引擎。

## 9.2 任务信息

每个任务至少显示：

- 任务名称。
- 任务类型。
- 当前状态。
- 当前阶段。
- 真实进度（如果可获得）。
- 开始时间。
- 已用时间。
- 输出位置。
- 错误信息。
- 重试入口。

## 9.3 任务状态

统一定义：

- 等待中。
- 运行中。
- 暂停。
- 已完成。
- 失败。
- 已取消。
- 需要用户操作。

不得把不同任务的阶段简单转换成不真实的统一百分比。

如果任务没有可靠的百分比，应显示阶段进度或不确定状态。

## 9.4 任务操作

支持：

- 暂停。
- 继续。
- 取消。
- 重试。
- 查看详情。
- 打开输出位置。
- 查看错误日志。

只有底层任务确实支持暂停或恢复时，才显示对应按钮。

## 9.5 后台通知

任务完成后提供轻量通知：

- AI 分析完成。
- 下载完成。
- 转换完成。
- 任务失败。
- 笔记保存失败。

通知可点击进入相关任务。

通知不得展示 API Key、敏感路径之外的个人信息或完整私密笔记正文。

# 十、P1：撤销、恢复与安全操作

## 10.1 统一撤销规则

建立 `UndoManager` 或复用已有撤销机制。

支持撤销的操作优先包括：

- 移动课程。
- 调整课程分类。
- 移动笔记。
- 重命名。
- 收藏状态变更。
- 批量整理。
- 删除前的回收站操作。

## 10.2 撤销提示

示例：

“已将课程移动到 UE5。”

[撤销]

撤销按钮应在合理时间内可用，并显示明确结果。

如果撤销失败，必须保留当前状态并提示原因。

## 10.3 操作历史

可选记录最近操作：

- 操作名称。
- 操作时间。
- 受影响对象。
- 是否可撤销。

默认不保存完整敏感内容。

## 10.4 危险操作

以下操作必须谨慎处理：

- 永久删除。
- 批量删除。
- 覆盖已有文件。
- 清空回收站。
- 覆盖历史版本。

必须提供明确确认。

“从学习库移除”不能自动删除磁盘源文件。

# 十一、P2：统一加载、空状态与错误反馈

## 11.1 加载状态

对于加载较慢的页面，使用稳定的骨架屏或局部加载提示。

避免：

- 整个页面闪白。
- 内容先挤在一起再突然展开。
- 面板高度剧烈跳动。
- 重复显示加载动画。
- 页面加载时无法操作无关功能。

## 11.2 空状态

为以下场景提供有用的下一步操作：

- 没有课程。
- 没有笔记。
- 没有搜索结果。
- 没有 AI 分析记录。
- 没有后台任务。
- 没有历史版本。

例如空课程库提供：

- 添加视频。
- 导入文件。
- 打开下载。
- 查看使用说明。

## 11.3 错误反馈

错误信息需要包括：

1. 发生了什么。
2. 可能的原因。
3. 当前数据是否已保存。
4. 可以执行的下一步操作。

不要只显示“操作失败”。

AI 错误必须保留已完成结果，并允许重试失败阶段。

Obsidian 联动失败时必须继续允许用户在映流中编辑 Markdown。

# 十二、P2：统一微交互与视觉反馈

## 12.1 设计变量

统一管理：

- 字体。
- 字号。
- 间距。
- 圆角。
- 边框。
- 强调色。
- hover 色。
- focus 状态。
- disabled 状态。
- 弹层层级。
- 阴影。
- 动画时长。

不允许各个模块随意使用互相冲突的设计值。

## 12.2 动画原则

动画只服务于：

- 展开和折叠。
- 弹层打开和关闭。
- 拖拽反馈。
- 状态变化。
- 页面区域切换。

避免：

- 大面积持续动画。
- 复杂粒子效果。
- 影响滚动性能的滤镜。
- 对大列表中的每个元素同时执行重动画。

提供减少动画选项，并遵循系统减少动态效果偏好。

## 12.3 统一反馈状态

所有主要交互组件都需要明确的：

- 默认状态。
- 悬停状态。
- 按下状态。
- 焦点状态。
- 禁用状态。
- 加载状态。
- 错误状态。

键盘焦点不能被隐藏。

# 十三、P2：AI 工作流联动

## 13.1 当前视频与知识库联动

增加快捷操作：

- 当前字幕生成笔记。
- 当前章节生成总结。
- 当前时间点创建笔记。
- 选择字幕后提问。
- AI 总结追加到现有笔记。
- 将分析结果整理为指定知识模板。

## 13.2 AI 修改保护

AI 生成内容后：

- 显示预览。
- 支持差异比较。
- 用户确认后应用。
- 保留撤销能力。
- 保存失败时保留生成结果。

禁止 AI 自动覆盖用户原笔记。

## 13.3 AI 任务后台化

长时间分析可以在用户切换页面后继续运行。

但必须使用现有任务管理机制，确保：

- 页面切换不取消任务。
- 任务状态可恢复。
- 重复点击不会创建重复任务。
- 任务失败能够重试。
- 用户主动取消后正确停止任务。

## 13.4 隐私控制

发送视频字幕、关键帧或笔记给 DeepSeek 之前，必须遵循现有 AI 数据发送设置。

工作区自动化不能绕过用户的隐私选择。

# 十五、性能与稳定性要求

## 15.1 大数据量

测试：

- 1000 条课程。
- 5000 条课程。
- 1000 篇笔记。
- 多个并行任务。
- 长 Markdown 笔记。
- 长视频字幕列表。

根据实际性能决定是否需要虚拟列表。

不要为所有列表无条件引入复杂虚拟化。

## 15.2 事件管理

- 不重复注册全局快捷键。
- 不重复添加窗口监听。
- 不重复创建 ResizeObserver。
- 组件卸载时清理事件。
- 拖拽过程中不能持续触发大量昂贵的布局计算。
- 输入时避免对整个应用进行无必要的重渲染。

## 15.3 性能目标

在目标 Windows 测试机上：

- 命令面板打开应保持流畅。
- 快捷键不应出现明显延迟。
- 普通面板展开与收起应保持流畅。
- 大列表滚动不能出现明显卡顿。
- 播放器布局调整不能造成明显黑屏。
- AI 后台运行不应阻塞用户编辑笔记。

这些目标必须通过实测记录，不得只根据代码推测性能达标。

# 十九、最终产品标准

映流 v0.5.2 的目标不是让软件看起来功能更多，而是让用户能够更自然、更高效、更安全地完成任务。

最终应具备：

- 键盘优先的全局操作。
- 上下文感知的右键菜单。
- Obsidian 式实时编辑。
- 专业播放器交互。
- 自适应布局。
- 可保存的工作区预设。
- 统一后台任务中心。
- 可撤销的关键操作。
- 清晰的加载、错误和成功状态。
- 视频、字幕、AI、知识库之间的连贯工作流。

**核心原则：减少点击、减少打断、减少等待中的不确定性、减少数据丢失风险。**

任何新增交互都必须回答一个问题：

它是否让用户更快、更自然或更安全地完成实际任务？

如果不能，就不应仅仅为了“高级感”而加入。

最终目标：将映流打造为一款兼具专业桌面软件效率、Obsidian 知识管理能力和 AI 视频学习能力的本地学习工作台。

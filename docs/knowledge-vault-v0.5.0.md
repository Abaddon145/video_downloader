# 映流知识库（v0.5.0）

映流知识库使用普通 Markdown 文件作为笔记本身。文件可由映流和其他 Markdown 编辑器读取；搜索、标签、双向链接等索引保存在应用的 `learning.db` 中，属于可重建的辅助数据。知识库后端已通过本机 Phase 8 验收，知识库专用编辑和浏览界面（Phase 9）以及分析后自动生成笔记（Phase 11）尚未完成，因此本文描述已实现的文件与后端能力，不代表这些界面或自动流程已经可用。

## 选择知识库

默认位置是系统“文档”目录下的 `映流知识库` 文件夹。也可以选择已有的本地磁盘文件夹；创建新目录时，应用会在所选位置建立它。知识笔记默认放在知识库中的 `映流` 文件夹，附件目录名为 `Attachments`。后端设置统一保存这两个目录名。知识库设置和索引保存在应用数据目录；笔记、图片及其他用户文件留在所选文件夹中。

知识库必须是本地磁盘上的绝对路径。应用以目录身份标识当前知识库，每次文件操作都会核对该标识；切换知识库后，旧标识发起的操作会被拒绝，防止旧页面误写入新位置。系统文档目录的默认路径只提供建议，实际使用仍以用户选定并成功打开的路径为准。

## 文件与安全边界

笔记是 UTF-8 Markdown，单文件最多 5 MiB。支持 PNG、JPG/JPEG、GIF、WebP、BMP 和 AVIF 图片附件，单次读取最多 8 MiB；SVG 等其他格式不会作为图片附件读取。目录浏览和移动操作受条目数与深度限制，索引扫描单次最多检查 10,000 个条目或 256 MiB 内容。

路径使用相对于知识库根目录的形式，例如 `映流/学习.md`。绝对路径、路径穿越、Windows 设备名、备用数据流、隐藏或系统文件以及 `.obsidian`、`.git`、`node_modules` 和应用回收目录等受保护位置会被拒绝或隐藏。底层逐级使用 Windows 目录句柄打开路径，并拒绝重解析点（包括符号链接和 junction）及多重硬链接；根目录若被替换也会被识别。应用不会创建、修改或打包 `.obsidian` 配置，也不要求安装 Obsidian。

## 编辑、移动与删除

保存笔记时，应用根据读取时的文件哈希检查磁盘版本。如果文件已被外部编辑，保存会返回冲突和当前磁盘内容，不会静默覆盖；重新读取或处理冲突后，再基于最新版本保存。文件内容通过临时文件写入并原子替换，降低写到一半留下损坏文件的风险。应用内部操作会串行保护同一知识库的变更；外部编辑器不参与这把锁，因此它不能让并发外部写入变成事务性协作。

新建文件不会覆盖已有文件。重命名和移动也不会覆盖目标。删除会把文件移入知识库内的 `.yingliu-trash` 回收目录；删除笔记时同样会核对预期哈希。数据库索引可能在文件保存成功后更新失败；这种情况下文件仍是已保存的真源，应用会报告索引警告，之后可重新扫描。

## 搜索、标签与链接

扫描知识库会把 Markdown 内容及可识别的标题、标签和链接写入 SQLite 索引。若 SQLite 构建提供 FTS5，搜索会使用它加速；否则使用内置文本匹配。知识库搜索每页最多返回 50 条，标签接口最多返回 5,000 个不同标签。搜索索引可从磁盘文件重新建立，数据库不是笔记内容的唯一副本。

扫描会跳过无法读取或超过 5 MiB 的笔记，并报告不完整状态。只有完整扫描成功后，才会清理磁盘上已不存在文件对应的旧索引；遇到错误、达到上限或扫描不完整时，会保留未能确认的旧索引，避免一次部分扫描把搜索结果删掉。目录列表、逐级读取与扫描并非针对外部程序写入形成的原子快照；外部程序同时修改目录时，请在修改完成后重新扫描。

索引器识别常见 YAML frontmatter 标题和标签、正文中的 `#标签`，以及 `[[笔记]]`、`[[路径/笔记#标题|显示名]]` 形式的 Wiki 链接。代码片段、围栏代码和图片嵌入不会作为普通文字链接提取。链接解析可按同目录、知识库内路径和文件名查找候选；存在多个匹配时会返回候选，不会假定唯一目标。反向链接和标签来自索引，因此外部编辑后的结果要等重新扫描更新。

## 与 Obsidian 一起使用

知识库是普通文件夹，可直接用 Obsidian 打开。映流还可为笔记生成经过 URL 编码的 `obsidian://open` 链接并请求系统启动 Obsidian；若系统没有可用的 Obsidian 启动程序，笔记仍保留在知识库中。该功能是可选的外部打开入口，不代表映流依赖 Obsidian，也不表示已实现 Obsidian 插件或实时同步。

## 当前实现与验收状态

AI 功能目前整合在学习库和播放器中（摘要、字幕、提问、笔记相关面板），独立 AI 页面已移除。知识库专用 UI 尚未完成，分析完成后生成或更新 Markdown 笔记、截图附件与时间链接也仍在待实现阶段。

后端测试覆盖了文件冲突与不覆盖、路径保护、大小限制、硬链接拒绝、junction/目录替换防护、回收、索引重建及不完整扫描保留旧索引等情形。本机具体结果见 [Phase 8 验收记录](evidence/ai-v0.5.0/phase8/acceptance.md)，最终完整验收仍待后续阶段；这些测试不能据此推断所有 Windows 配置或真实 Obsidian 安装均已验证。
